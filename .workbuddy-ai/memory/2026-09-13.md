LangChain 17 Feb 2026, martinfowler.com 2 Apr 2026)

### Temuan inti
- **Harness engineering** = disiplin merancang seluruh infrastruktur di sekitar model
  (bukan modelnya). Formula: `Agent = Model + Harness`. Pencetus istilah: **Mitchell Hashimoto**
  (5 Feb 2026, "My AI Adoption Journey" Step 5). Diformalkan OpenAI, disistematisasi Fowler/Böckeler.
- Kerangka paling berguna: **Guides (feedforward) vs Sensors (feedback)**, masing-masing
  **computational** (deterministik) atau **inferential** (LLM-as-judge). Plus **steering loop**.
- Akar kata: test harness (1997) → fuzzing harness → eval harness → agent harness. Logika identik
  40 tahun: bungkus unit eksekusi yang tidak bisa dipercaya penuh.

### Verdict atas Bab 27
**YA — sah sebagai harness engineering**, tepatnya kategori **"outer harness untuk pengguna
coding agent"** (istilah Fowler). Yang sudah kuat: guides lengkap (AGENTS.MD, architect pack,
constitution, dry run gate), sensors lengkap (acceptance-runner, browser-skill, security-auditor,
deploy-gate, observability, debugging routing), **steering loop eksplisit** (27.4b: catat akar
masalah + perbarui runbook), dan **session handoff sebagai harness primitive** (27.7) — yang terakhir
ini implementasi paling matang dari yang ditemukan di literatur.

**Gap (3 utama):** (1) tidak ada lint kustom / structural test yang di-generate → constraint masih
tekstual, padahal OpenAI menegaskan teks "rots instantly, hard to verify mechanically";
(2) tidak ada entropy "garbage collection" terjadwal; (3) tidak ada cost envelope per task.

## Rencana Menutup Gap Harness Engineering

**Alasan terkuat tiap gap (untuk diingat):**
1. Mekanis — OpenAI: teks "rots instantly" & "hard to verify mechanically"; yang mekanis jadi

   diotomasi, cleanup scale proporsional dengan throughput. Fowler: sensor drift harus jalan
   "outside the change lifecycle".
3. Cost envelope — cost overrun = **sinyal reliabilitas**, bukan sekadar pemborosan.
   LangChain: batasi reasoning justru MENAIKKAN skor (53.9% → 63.6%).
4. Metrik harness — Fowler: "If sensors never fire, is that high quality or inadequate detection?"

## Kebijakan Model: Agent DILARANG memilih model

**Konteks dari user:** memakai model GRATIS dari beberapa provider — tidak ada jaminan akses model
tier atas. Jadi klausa skill vendor "use the most capable available model" tidak bisa dijalankan.

**Hasil inspeksi langsung `obra/superpowers` (bukan asumsi):**
| Skill | Rujukan model | Verdict |
|---|---|---|
| `using-git-worktrees` | **0** | aman apa adanya |
| `dispatching-parallel-agents` | **0** | aman apa adanya |
| `subagent-driven-development` | **9 di SKILL.md + field `[MODEL]` WAJIB di 3 template** | wajib override |

Detail penting: `subagent-driven-development` punya bagian `## Model Selection` (± 40 baris) yang
menyuruh agent memilih tier per tugas, DAN tiga file template (`implementer-prompt.md`,
`task-reviewer-prompt.md`, `re-review-prompt.md`) punya field
`model: [MODEL — REQUIRED: choose per SKILL.md Model Selection; ...]`.

**Insight kunci:** field `[MODEL]` yang WAJIB itu justru menguntungkan — ia titik kontrol bersih.
Tidak perlu melawan skill-nya; cukup **mengisi placeholder-nya lebih dulu** dari tabel.
Agent jadi menyalin, bukan memilih.

**Artefak yang dibuat (3 file baru):**
1. `MODEL-POLICY.md` (root) — tabel peran→model, aturan R1–R7, DEFAULT = "model sesi ini,
   jangan ganti" (berfungsi tanpa diisi apa pun), tangga eskalasi §4, blok siap tempel AGENTS.MD,
   prosedur verifikasi §6.
2. `skills-vendor/OVERRIDES.md` — registry override O-1…O-4 (klausa mana, kutipan asli, alasan,
   pengganti, efek). Menjaga file vendor tetap VERBATIM sesuai 27.4b.
3. `AGENTS.MD` (root, BARU — sebelumnya repo ini tidak punya) — blok kebijakan model + pointer.

**Keputusan desain penting:** eskalasi kemampuan DIGANTI, bukan dihapus. Tangga baru:
`1–3 resume (model SAMA) → 4–5 fresh eyes (model SAMA) → lewat 5 re-scope brief → STOP ke manusia`.
Prinsipnya: kalau kemampuan model tidak bisa ditambah, yang ditambah adalah kejelasan spec dan
kecilnya tugas.

**RENCANA diupdate:** §6.3 tabel dipisah per skill, §6.4 baru ("Batasan Lingkungan: Model Gratis
Multi-Provider"), H-006 dapat prasyarat, tabel risiko +3 baris, A.1 diperbarui.

**Feedback user:** *"tidak biar saya saja yang mengatur model apa yang akan digunakan untuk alur
tersebut"* — user menolak desain `DEFAULT = model sesi ini, jangan ganti`. Ia ingin **dirinya
sendiri satu-satunya yang mengatur model**.

**Perubahan yang dilakukan (semua file diupdate, tidak ada sisa DEFAULT):**
- `MODEL-POLICY.md` §3.1: `DEFAULT` → **"TIDAK ADA DEFAULT — agent WAJIB berhenti dan bertanya"**.
  Daftar larangan eksplisit: dilarang pakai model sesi ini, model tugas sebelumnya, tebakan dari
  nama/tier/reputasi, model dari contoh/dokumentasi, atau "model teraman menurut agent".
- §3.2 jadi **"Deklarasi manusia"** (bukan tabel sistem) + §3.3 baru "Nilai yang boleh dipakai agent"
  (3 sumber sah, semuanya dari manusia).

  `[MODEL]` ke ledger tiap dispatch supaya bisa diaudit.
- §4: tambah paragraf — user boleh ganti model kapan saja, tapi agent DILARANG **mengusulkan**
  model. Yang boleh: melaporkan keadaan ("gagal 4 kali; re-scope atau ganti model — mana?").
- §6 verifikasi: ujian #1 sekarang **kosongkan tabel → apakah agent berhenti atau mengisi sendiri**.
  Ini ujian terpenting.
- `AGENTS.MD`: tambah larangan mengusulkan model + larangan pakai model sesi ini + R8.

> Manusia mengatur model, agent mengerjakan tugas. Kalau agent tidak tahu model apa yang dipakai,
